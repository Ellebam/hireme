## Findings

### T-006: Section Editors

All editors are at `web/src/components/editor/editors/` and share a common pattern:
- Props: `{ sectionId: string; content: <ContentType> }`
- All use `useEditorStore()` — specifically `updateSectionContent`

#### 1. PersonalEditor (`PersonalEditor.tsx`)
- **Props:** `{ sectionId: string; content: PersonalContent }`
- **Store:** `updateSectionContent` from `useEditorStore`
- **Key elements:** Labels for "First Name", "Last Name", "Job Title", "Email", "Phone", "Location", "Links"; Inputs with ids `firstName`, `lastName`, `jobTitle`, `email`, `phone`, `location`; "Add Link" button; Empty state "No links added yet"
- **Pattern:** Inline editing — no modal

#### 2. SummaryEditor (`SummaryEditor.tsx`)
- **Props:** `{ sectionId: string; content: SummaryContent }`
- **Store:** `updateSectionContent` from `useEditorStore`
- **Key elements:** Label "Professional Summary"; Textarea with id `summary`; Character counter; Tips section
- **Pattern:** Inline editing — no modal

#### 3. ExperienceEditor (`ExperienceEditor.tsx`)
- **Props:** `{ sectionId: string; content: ExperienceContent }`
- **Store:** `updateSectionContent` from `useEditorStore`
- **Key elements:** "Add Experience" button; Entry count text; Entry cards with position/company; Empty state "No work experience added"
- **Pattern:** Modal editing via `ExperienceEntryModal` (Dialog)
- **Sub-components:** `ExperienceEntryCard`, `ExperienceEntryModal`

#### 4. EducationEditor (`EducationEditor.tsx`)
- **Props:** `{ sectionId: string; content: EducationContent }`
- **Store:** `updateSectionContent` from `useEditorStore`
- **Key elements:** "Add Education" button; Entry count text; Entry cards with degree/institution; Empty state "No education added"
- **Pattern:** Modal editing via `EducationEntryModal` (Dialog)
- **Sub-components:** `EducationEntryCard`, `EducationEntryModal`

#### 5. SkillsEditor (`SkillsEditor.tsx`)
- **Props:** `{ sectionId: string; content: SkillsContent }`
- **Store:** `updateSectionContent` from `useEditorStore`
- **Key elements:** "Add Category" button; Category count text; Category cards with name; Skill tags; Empty state "No skill categories added"
- **Pattern:** Inline editing with tag-based skill cards
- **Sub-components:** `SkillCategoryCard`, `SkillTag`

#### 6. LanguagesEditor (`LanguagesEditor.tsx`)
- **Props:** `{ sectionId: string; content: LanguagesContent }`
- **Store:** `updateSectionContent` from `useEditorStore`
- **Key elements:** "Add Language" button; Entry count text; Language rows with language input + proficiency select; Empty state "No languages added"
- **Pattern:** Inline editing — no modal
- **Sub-components:** `LanguageEntryRow`

### T-007: Page Components

#### Dashboard (`web/src/app/page.tsx`)
- **Default export:** `DashboardPage`
- **Dependencies:**
  - `api.cv.get()` — fetches user CV on mount
  - `api.cv.delete(id)` — delete handler
  - `AppShell` layout wrapper (renders `Header`)
  - `next/link` — navigation links
- **Key elements:** Heading "Dashboard"; Subtitle "Manage your CV..."; Button "Edit CV" or "Create CV"; Loading skeleton; Error state; Empty state "No CV yet"; CV card with title, template badge, section count
- **Sub-components:** `CVCard`, `EmptyState`, `ErrorState`, `DashboardSkeleton`
- **Mock needs:** `@/lib/api` (api.cv.get, api.cv.delete)

#### Editor (`web/src/app/editor/page.tsx`)
- **Default export:** `EditorPage`
- **Dependencies:**
  - `api.cv.get()` — loads CV
  - `api.cv.create()` — creates if not found
  - `useEditorStore()` — `setCV`, `reset`
  - `useAutoSave()` — hook
  - `useKeyboardShortcuts()` — hook
  - `starterTemplate()` — from templates
  - `logger` — logging
  - `next/navigation` — `useRouter`
  - `EditorLayout` — main layout
  - `TooltipProvider` — from radix
- **Key elements:** Loading state "Loading editor..."; Error state "Something went wrong"; `EditorLayout` component on success
- **Mock needs:** `@/lib/api`, `@/hooks` (useAutoSave, useKeyboardShortcuts), `@/lib/logger`, `@/lib/templates`, `@/stores` (useEditorStore)

### Test Patterns
- Import `describe, it, expect, vi` from `vitest`
- Import `render, screen` from `@/test/utils` (custom wrapper)
- Mock Zustand stores using `vi.mock('@/stores', ...)` or set state directly with `useEditorStore.setState()`
- Mock API with `vi.mock('@/lib/api', ...)`
- Existing tests are pure unit tests (store, api client, templates, hooks) — **no component render tests exist yet**

## Architect Handoff

### Decisions Needed

**Quick Decision: Test file location pattern**
- **Option A (Recommended):** Colocate tests next to source: `editors/__tests__/PersonalEditor.test.tsx`
- **Option B:** Centralized: `web/src/__tests__/components/editors/PersonalEditor.test.tsx`
- **Recommendation:** Option A — follows common React convention, matches existing colocated pattern (e.g. `editor-store.test.ts` next to `editor-store.ts`)

**Quick Decision: Store mocking strategy for editors**
- **Option A (Recommended):** Mock `@/stores` module with `vi.mock()` — return `updateSectionContent: vi.fn()`
- **Option B:** Use real store, set state with `useEditorStore.setState()` before each test
- **Recommendation:** Option A for smoke tests — lighter, only verifies render, not store integration

**Quick Decision: API mocking for pages**
- **Option A (Recommended):** Mock `@/lib/api` to return resolved/rejected promises as needed per test
- **Recommendation:** Only option — pages call API on mount, must be mocked
